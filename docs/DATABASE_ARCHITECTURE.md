# LogCmd 数据库架构设计

## 设计目标

- **统一元数据管理**：命令执行信息、项目属性、统计结果存储于 SQLite，日志文件存放原始输出
- **高性能查询**：避免扫描日志文件，通过数据库索引实现快速检索
- **可扩展性**：使用 JSON 字段支持未来功能扩展，保持向后兼容
- **自动化迁移**：程序启动时自动检测并迁移旧版本数据结构

## 核心表结构

| 表名 | 职责 | 关键字段 |
|------|------|----------|
| `projects` | 项目元数据与统计汇总 | 路径、名称、标签、命令统计、执行时长 |
| `command_history` | 命令执行历史 | 项目ID、命令、时间、退出码、日志路径 |
| `project_stats_cache` | 按日期聚合的统计缓存 | 项目ID、日期、命令分布、成功率 |
| `system_config` | 系统配置 | 版本号、保留策略 |

## 架构分层

```
┌─────────────────────────────────────┐
│     CLI Commands (run/search/stats) │
└────────────┬────────────────────────┘
             │
┌────────────▼────────────────────────┐
│  Persistence Layer (协调层)         │
│  - RunRepository (命令记录)         │
│  - StatsUpdater (统计更新)          │
└────────────┬────────────────────────┘
             │
┌────────────▼────────────────────────┐
│  Database Layer                     │
│  - Registry (项目管理)              │
│  - History (历史记录)               │
│  - Stats (统计缓存)                 │
└─────────────────────────────────────┘
```

**设计原则**：
- **单一职责**：每层只关注特定领域逻辑
- **依赖倒置**：上层依赖接口而非具体实现
- **关注点分离**：日志输出、元数据采集、数据持久化相互解耦

## 数据流

1. **命令执行流程**
   - 执行器输出日志到文件
   - 持久化层记录命令元数据到 `command_history`
   - 增量更新 `projects` 表统计字段

2. **统计查询流程**
   - 优先读取 `project_stats_cache` 缓存
   - 缓存未命中时从 `command_history` 聚合生成
   - 完整日志内容按需从日志文件读取

3. **数据迁移流程**
   - 启动时检测表结构版本
   - 事务性执行迁移脚本
   - 失败自动回滚，保证数据完整性

## 关键设计决策

### 增量统计
所有统计字段采用增量更新而非全量扫描，避免性能瓶颈。

### JSON扩展字段
使用 JSON 存储可变结构数据（标签、配置、分布统计），减少表结构变更。

### 路径与时间规范
- 路径统一使用绝对路径存储
- 时间统一使用 UTC 存储，展示层负责本地化转换

### 缓存策略
按日期维度缓存统计数据，平衡查询性能与存储开销。

## 扩展性设计

- **标签系统**：预留 `tags` 和 `project_tags` 表支持项目分类
- **版本管理**：通过 `system_config` 表记录架构版本
- **水平扩展**：设计支持未来多数据库实例分片
